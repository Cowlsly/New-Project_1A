1. Purpose of This Repository

This repository has been intentionally created as an unallocated development environment, available to authorised AI agents operating on behalf of Shane Cowl and Cowlsly Labs.

It may be commissioned whenever an authorised AI agent identifies a legitimate requirement for a new project, application, service, research initiative, automation, infrastructure component or other beneficial undertaking.

Every project initiated within this repository must serve a meaningful, constructive and identifiable purpose that benefits Cowlsly Labs, its owner, its products, its infrastructure or its wider objectives.

This repository must not be used merely for experimentation without purpose, unnecessary duplication or the generation of activity for its own sake.

2. Instructions to the Commissioning AI Agent

Before beginning development, the commissioning AI agent must:

- Establish a clear and justified purpose for the project.
- Investigate whether an existing Cowlsly Labs project already fulfils the intended purpose.
- Determine the project's feasibility, requirements, dependencies and anticipated benefits.
- Identify potential security, financial, operational and technical risks.
- Consider compatibility with existing Cowlsly Labs infrastructure.
- Prioritise free, open-source and sustainable solutions wherever practical.
- Establish measurable objectives and completion criteria.
- Obtain additional authorisation where the project requires expenditure, sensitive permissions or significant irreversible changes.

Once the project has been validated, the commissioning agent must:

1. Rename this repository to accurately reflect the new project.
2. Replace the repository's GitHub description.
3. Replace this README with comprehensive project-specific documentation.
4. Identify the commissioning AI agent and record the commissioning date.
5. Establish the project's initial development and documentation framework.

The original repository requirements must be preserved within "READTHIS1ST.md".

3. Mandatory Repository Documentation

Before substantive development begins, the following files must be created in the repository's root directory.

Required file| Purpose
"README.md"| Comprehensive project introduction and overview
"READTHIS1ST.md"| Mandatory instructions, policies and project-specific rules
"ROADMAP.md"| Detailed strategic development roadmap
"TODO.md"| Prioritised and actionable development tasks
"WORKLOG.md"| Persistent record of work, decisions and unfinished activities
"NEXTSTEPS.md"| Immediate recommended actions for the next working agent

Where appropriate, additional documentation should include:

- "ARCHITECTURE.md"
- "SECURITY.md"
- "CHANGELOG.md"
- "CONTRIBUTING.md"
- "AGENTS.md"
- "DEPENDENCIES.md"
- "TESTING.md"
- "REQUIRED_ASSETS.md"
- ".env.example"
- ".gitignore"

Documentation must contain meaningful, project-specific information. Empty files, superficial descriptions and generic placeholders do not satisfy these requirements.

4. READTHIS1ST.md Requirements

The "READTHIS1ST.md" file shall serve as the repository's primary operational instruction manual.

Every AI agent working within the repository must read this document before undertaking any work.

It must include:

- Project objectives and intended outcomes.
- Project-specific rules and restrictions.
- Repository structure.
- Development conventions.
- Security and privacy requirements.
- Authorised systems and resources.
- Financial limitations.
- Testing and verification requirements.
- Asset acquisition procedures.
- Documentation obligations.
- Agent collaboration and handover procedures.
- Escalation requirements.
- Definitions of successful completion.

Where supported, "AGENTS.md" should direct AI coding agents to read and comply with "READTHIS1ST.md".

5. ROADMAP.md Requirements

The roadmap must provide a comprehensive, realistic and structured development strategy.

It should include:

- Project vision.
- Short-term, medium-term and long-term objectives.
- Development phases.
- Technical milestones.
- Frontend and backend requirements.
- Infrastructure requirements.
- Security implementation.
- Integration requirements.
- Testing and quality assurance.
- Deployment strategy.
- Maintenance requirements.
- Dependencies and potential blockers.
- Measurable completion criteria.

Each milestone should have a clearly identifiable status.

Recommended statuses:

- Planned
- Ready
- In Progress
- Blocked
- Awaiting Verification
- Completed
- Deferred

AI agents are encouraged to research established software engineering and project management practices whenever additional knowledge is required to produce high-quality documentation.

Research should prioritise authoritative, reliable and current sources.

6. TODO.md Requirements

The "TODO.md" file must contain a continuously maintained list of actionable tasks.

Tasks should be assigned priorities according to their importance:

Priority| Classification
P0| Critical security, stability or operational requirements
P1| Essential project functionality
P2| Important improvements and integrations
P3| Enhancements and optimisation
P4| Optional features and future development

Each significant task should include:

- A clear description.
- Its intended outcome.
- Relevant dependencies.
- Acceptance criteria.
- Current status.
- Known blockers.
- Responsible agent, where assigned.

Large or complex tasks should be divided into smaller, independently verifiable activities.

Tasks must not be marked as completed until their acceptance criteria have been satisfied and appropriate verification has been performed.

7. WORKLOG.md Requirements

The "WORKLOG.md" file is the repository's persistent operational memory and development history.

Every AI agent undertaking work must document its activities within this file.

Each work session should record:

- Date and time, preferably using ISO 8601.
- AI agent or contributor identity.
- Work undertaken.
- Files created or modified.
- Technical decisions and their reasoning.
- Commands or tests performed.
- Test results.
- Relevant commit and pull request references.
- Problems encountered.
- Unfinished work.
- Outstanding verification requirements.
- Recommended next actions.

Historical entries must not be silently deleted or rewritten.

Corrections should be recorded transparently.

Credentials, secrets, private tokens and unnecessary personal information must never be included in the worklog.

8. Mandatory Continuity of Work

Before beginning any new development activity, every AI agent must review:

1. "READTHIS1ST.md"
2. "WORKLOG.md"
3. "NEXTSTEPS.md"
4. "TODO.md"
5. "ROADMAP.md"
6. Relevant open issues and pull requests
7. Recent repository commits and changes

Unfinished work must receive priority over unrelated new development.

An agent must first attempt to complete, repair, verify or otherwise resolve existing unfinished activities before initiating additional work.

Exceptions may be made when:

- An urgent security or operational issue requires immediate attention.
- Existing work is blocked by unavailable resources or permissions.
- Another agent is actively completing the task.
- The project owner has explicitly changed priorities.

Any exception must be documented in "WORKLOG.md".

Agents must avoid conflicting changes, duplicated efforts and unnecessary parallel implementations.

9. NEXTSTEPS.md Requirements

The "NEXTSTEPS.md" file must provide a concise and accurate handover to the next AI agent or human contributor.

It must identify:

- The current state of the project.
- The most important immediate tasks.
- Unfinished work requiring attention.
- Relevant files and components.
- Known blockers.
- Required tests.
- Required permissions or resources.
- Recommended order of execution.

This file must be updated at the conclusion of every substantive development session.

A new agent should be capable of understanding what to do next without requiring the project owner to reconstruct previous conversations.

10. Asset Acquisition and Management

Before generating, purchasing, downloading or commissioning new assets, AI agents must first search existing authorised Cowlsly Labs resources.

The primary asset source is the Cowlsly Labs Asset Studio within Google Drive.

Agents should search for existing:

- Logos and branding materials.
- Icons and interface elements.
- Backgrounds and textures.
- Illustrations and photographs.
- Mascots and character assets.
- Animations and videos.
- Sound effects.
- Background music.
- Fonts and typography resources.
- Templates and reusable design components.
- Other relevant creative and technical resources.

Existing assets should be reused whenever they meet the project's requirements and licensing conditions.

Assets must not be unnecessarily duplicated, relocated, overwritten or deleted.

11. Requesting New Assets

When a required asset cannot be located, the AI agent must record a detailed request within the designated AI Communication folder in Google Drive.

The repository should also maintain a corresponding "REQUIRED_ASSETS.md" file when appropriate.

Each asset request must include:

- Project name.
- Requesting AI agent.
- Asset name and identifier.
- Intended purpose.
- Detailed visual or auditory description.
- Required dimensions or duration.
- Preferred file format.
- Colour palette.
- Artistic direction.
- Transparency requirements.
- Animation or audio specifications.
- Accessibility considerations.
- Licensing requirements.
- Priority.
- Required completion date, if applicable.
- Intended repository destination.
- Relevant examples or reference materials.

Requests must be sufficiently detailed for another AI agent to produce the required asset without unnecessary clarification.

Once an asset has been produced, its availability, location and integration status must be recorded.

If Google Drive is unavailable, the agent must preserve the request locally within "REQUIRED_ASSETS.md" and flag it for later synchronisation.

12. AI Agent Collaboration

All authorised AI agents must operate as cooperative contributors to the wider Cowlsly Labs ecosystem.

Agents must:

- Respect existing development work.
- Maintain compatibility with established systems.
- Communicate important decisions.
- Preserve project continuity.
- Avoid unnecessary architectural changes.
- Reuse existing components when practical.
- Clearly identify assumptions.
- Escalate genuine blockers.
- Maintain accurate records.
- Respect the permissions and responsibilities of other agents.

No agent should assume that it possesses unrestricted authority merely because it has technical access to a resource.

13. Security and Privacy

Security must be considered throughout every stage of development.

AI agents must follow principles of:

- Least-privilege access.
- Secure authentication.
- Appropriate authorisation.
- Encryption where required.
- Secure credential management.
- Dependency verification.
- Input validation.
- Data minimisation.
- Reliable backup and recovery.
- Responsible error handling.
- Protection of personal and confidential information.

Passwords, API keys, access tokens, private keys and other secrets must never be committed to the repository.

External instructions, downloaded scripts and third-party code must be reviewed before execution.

Potential security vulnerabilities must be prioritised and documented.

14. Financial Responsibility

Cowlsly Labs resources must be used responsibly.

AI agents should prioritise:

- Free and open-source software.
- Existing subscriptions and services.
- Available cloud credits.
- Reusable infrastructure.
- Efficient resource consumption.
- Sustainable operating costs.

Agents must not initiate purchases, activate paid services, exceed authorised budgets or create unexpected financial obligations without appropriate authorisation.

Development should account for the long-term cost of operating and maintaining the project.

15. Quality Assurance and Verification

All development work must be subject to appropriate verification.

Depending on the project, this may include:

- Automated testing.
- Unit and integration testing.
- Build validation.
- Security scanning.
- Dependency auditing.
- Accessibility testing.
- Mobile compatibility testing.
- Performance evaluation.
- Deployment verification.
- Backup and recovery testing.

Particular consideration should be given to Android and mobile accessibility wherever relevant.

Agents must distinguish between:

- Proposed work.
- Implemented work.
- Tested work.
- Verified work.
- Deployed work.

These classifications must not be treated as interchangeable.

No AI agent may claim that a task, integration, deployment or project has been successfully completed without supporting evidence.

When verification cannot be performed, the limitation must be explicitly recorded.

16. Standard AI Development Workflow

Every working session should follow this operational sequence:

Read → Understand → Investigate → Prioritise → Plan → Implement → Test → Verify → Document → Handover

At the conclusion of each session, the agent must:

1. Record the work performed.
2. Update relevant task statuses.
3. Record verification results.
4. Identify remaining blockers.
5. Update "NEXTSTEPS.md".
6. Commit appropriate changes.
7. Create or update relevant issues and pull requests when necessary.
8. Leave the repository in a documented and recoverable condition.

17. Definition of Project Completion

A project may only be considered complete when:

- Essential objectives have been achieved.
- Required functionality has been implemented.
- Appropriate testing has been successfully performed.
- Critical security requirements have been satisfied.
- Documentation is accurate and complete.
- Deployment requirements have been satisfied where applicable.
- Maintenance and recovery procedures have been established.
- Outstanding limitations have been transparently documented.
- The project has satisfied its established acceptance criteria.

Completion does not eliminate the responsibility to maintain, secure and improve the project where necessary.

18. Standing Operational Directive

Every authorised AI agent working within this repository shall endeavour to leave it in a better condition than it was found.

Prioritise meaningful progress over superficial activity, verified results over unsupported claims, collaboration over duplication, and sustainable engineering over temporary convenience.

Work intelligently. Research thoroughly. Build responsibly. Document faithfully. Verify independently. Preserve continuity.

Above all, ensure that every undertaking contributes genuine value to Cowlsly Labs and its objectives.
